# Claude Handoff

This repository is collaborative, so check the working tree before edits and never overwrite
unrelated changes.

## Product Intent

Create a generic enterprise RAG platform in .NET. The system ingests `txt`, `md`, and `pdf`
documents from local files, S3 prefixes, and Azure Blob prefixes, normalizes text, chunks
content, embeds chunks, stores documents and chunks in a document database, indexes vectors
in Elasticsearch, and answers questions with grounded citations through configurable LLM
endpoints and `LLM_SYSTEM_PROMPT`.

## Repository Structure

```text
src/Rag.Core/              Core abstractions, models, adapters, strategies, pipelines, and DI
src/Rag.Providers.Aws/     AWS S3 document source (opt-in: AddRagAwsS3)
src/Rag.Providers.AzureBlob/ Azure Blob document source (opt-in: AddRagAzureBlob)
src/Rag.Providers.Cosmos/  Cosmos DB document store (opt-in: AddRagCosmos)
src/Rag.Providers.Mongo/   MongoDB document store and job store (opt-in: AddRagMongo)
src/Rag.Api/               ASP.NET Core API: async ingest, jobs, chunk preview, query, health, Swagger
src/Rag.Cli/               CLI: ingest, jobs status, chunk:preview, query, config
tests/Rag.Core.Tests/      Unit tests
tests/Rag.Cli.Tests/       CLI command and exit-code tests
tests/Rag.Evals.Tests/     Evaluation harness tests and retrieval regression floors
tests/Rag.Integration.Tests/ Integration/provider tests (Docker required, except AdapterSelectionTests)
evals/Rag.Evals/           Golden dataset, deterministic scorers, chunking benchmark, report writer
samples/                   Sample txt, md, and pdf inputs (handbook.pdf is generated by Rag.Evals)
```

Architecture, runtime selectors, and configuration keys are documented in [README.md](README.md).
Language and test conventions live in `.claude/rules/`, scoped by path.

## Invariants

- `Rag.Core` takes no provider SDK dependency. Backends live in `Rag.Providers.*`, register as keyed
  services, and are wired by an explicit `AddRag*` call. Requesting a provider whose package is not
  referenced must fail naming the missing package, never fall back to in-memory.
- Configuration binds to options classes. No environment reads inside pipeline logic; grounding
  prompts come from options, not literals.
- Package versions are pinned centrally in `Directory.Packages.props`.
- Generated artifacts are never hand-edited: `samples/handbook.pdf`, `evals/results/`, and the
  evaluation tables in `README.md`. Regenerate them (see below).
- Each project directory under `src/`, `tests/`, and `evals/` keeps a `README.md` describing purpose,
  usage, inputs/outputs, and dependencies.

## Verification

.NET SDK `10.0.301` is available locally. Builds treat warnings as errors
(`Directory.Build.props`), so `-warnaserror` matches CI.

```bash
dotnet build enterprise-rag-platform.sln -warnaserror
dotnet test enterprise-rag-platform.sln --filter "Category!=Integration"   # no Docker needed
```

`tests/Rag.Integration.Tests` needs a running Docker daemon (Testcontainers: LocalStack, Azurite,
MongoDB, Elasticsearch). With Docker running:

```bash
docker-compose up -d
dotnet test enterprise-rag-platform.sln
```

Regenerating the published evaluation tables — CI fails if they drift:

```bash
dotnet run --project evals/Rag.Evals -- report --write
git diff --exit-code -- README.md evals/results
```
